# Agy 会话检索与命名管家操作流程

本技能封装了本机 Google Antigravity CLI（`agy`）的本地会话（Thread）管理工作流，实现“纯自然语言驱动、零手动操作”的历史会话检索、批量规范化重命名与无效会话安全清理。

## 一、核心安全铁律（不可绕过）

1. **先只读预览、停下来等确认、再执行**：
   - 修改或删除任何会话前，必须先调用 `scan_agy_sessions` 读取真实会话内容与产物，再调用 `preview_session_changes` 生成并向用户完整展示**《清理排查清单》**（写明保留/拟清理/待确认及判断依据）和**《改名前后对照表》**（写明分类、原名、15~25字中文新名、字数与进入命令），然后**立即结束本轮输出**。
   - 只有当用户在下一条消息中明确回复确认后，才允许携带一次性 `confirmation_token` 与用户确认原话调用 `execute_session_changes`。
   - **严禁在同一轮对话中连续调用 `preview_session_changes` 与 `execute_session_changes`**，严禁代用户填写确认原话或自行跳过预览直接改库。
2. **防误杀硬约束（严禁以步数/轮次少武断判删）**：
   - **严禁仅因对话轮次少（如只有 1~2 轮）就判为无效会话。**
   - 必须依据 `scan_agy_sessions` 返回的真实对话首尾摘要与 `brain/<id>` 产物判断：凡包含有效结论、交付产物或复查价值的会话一律保留；对拿不准的会话必须放入 `uncertain` 待确认列表询问用户。
   - 仅将纯冒烟/连通性测试、0 轮空白会话、以及重复开启后中途断掉且已有完整替代会话的废会话列为 `deletes`。
3. **会话命名规范硬约束**：
   - 全部统一使用**简体中文**，长度控制在 **15~25 个字以内**（不含省略号 `...`/`…`、不用“新会话”等模糊词）。
   - **项目类会话**：固定采用 **`项目名称-简短说明`**（如 `Agy会话管家-需求对齐与基线建立`、`工作邮件插件-迁移至Agy与门禁验收`）。
   - **工具/运维类会话**：采用统一的 4 字中文分类前缀 + 具体完成事项，如 **`规则配置-xxx`**、**`插件与钩子-xxx`**、**`系统运维-xxx`**、**`日常工具-xxx`**、**`知识库-xxx`**。
4. **单一正式引擎与完整备份核验**：
   - 唯一通过本插件的 MCP 工具执行重命名与清理，禁止手写临时 SQL 或直接删除文件绕过完整备份与四处一致性回读核验。

## 二、历史会话检索流程（找会话）

当用户提供关键词、项目路径、截图或模糊描述寻找历史会话时：
1. 调用 `search_agy_sessions`（或 `scan_agy_sessions`）获取匹配结果。
2. 输出结果必须包含以下**三要素**：
   - **会话名称（及会话 ID）**
   - **定位依据**（为什么判断是这个会话，例如匹配的工作区目录、关键对话内容或产出文件）
   - **便捷进入方式**（直接给出可复制的 `agy --conversation <会话ID>` 命令）

---

## 三、会话整理（重命名与清理）两阶段流程

### 阶段 1：只读盘点与生成预览核对卡（先不执行）
1. **调用 `scan_agy_sessions`**：
   - 读取所有会话的当前标题、步数、`is_locked`（终端是否开启占用）、首尾提问与回答摘要、`artifacts` 产出物以及 `orphans`（无主孤立 `.lock` 文件）。
   - 若某会话摘要不足以判断价值，可按需只读查看 `brain/<id>/.system_generated/logs/transcript.jsonl` 确认真实内容。
2. **拟定分类与新名称（15~25 字以内简体中文）**：
   - **项目类**：`项目名称-简短说明`
   - **工具类**：`分类前缀-具体事项`（`规则配置-`、`插件与钩子-`、`系统运维-`、`日常工具-`、`知识库-`）
   - 已符合上述规范的保留会话无需重复列入 `renames`。
3. **甄别保留、拟清理与待确认会话**：
   - **拟清理（`deletes`）**：仅限 0 步空白会话、纯连通性/冒烟测试、或与另一完整会话首轮提示词完全相同但中途中断的无产物废会话。**当前正在对话的本窗口会话绝不列入 `deletes`**。
   - **待确认（`uncertain`）**：拿不准是否有复查价值的会话，单列询问用户。
   - **保留（`keeps`）**：所有包含业务结论、代码/文档修改或复查价值的会话，写明具体保留依据。
4. **调用 `preview_session_changes` 并停下等确认**：
   - 将 `preview_session_changes` 返回的完整核对卡（含《清理排查清单》、《改名前后对照表》及 `confirmation_token`）完整展示给用户。
   - 若待清理项中存在 `⚠️ 终端未关闭`，提醒用户执行前先顺手关闭对应的空闲终端窗口。
   - **立即结束本轮回复，等待用户确认**。

### 阶段 2：用户确认后备份、执行与回读核验
1. 收到用户在下一条消息中的明确同意回复后，调用 `execute_session_changes`，传入上一步的 `confirmation_token` 和用户的确认原话 `user_confirmation_quote`。
2. 若用户在确认时要求微调某条新名称或保留某条会话，必须先按微调后的方案重新调用 `preview_session_changes` 获取新令牌。
3. 执行完成后，向用户汇报：
   - 执行状态与四处一致性回读核验结果；
   - 完整备份目录路径及一键还原命令 `restore.py`。
